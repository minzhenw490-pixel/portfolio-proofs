## 二、9 个 Agent

| Agent | 角色卡 | 一句话 |
|---|---|---|
| **chief** | `agents/chief.md` | 总调度：判断类型 → 分派 → 汇总 → 交你确认 |
| **pm** | `agents/pm.md` | 产品经理：发现问题 → 验证 → 方案 → PRD → 数据验证 |
| **content** | `agents/content.md` | 内容运营：找问题 → 检查解释 → 做成内容 → 回收迭代 |
| **ops** | `agents/ops.md` | Web3 运营：活动 / 社群 / 内容 / 增长 / 复盘（按你的模板） |
| **research** | `agents/research.md` | 调研：用户 / 市场 / 竞品，结论可溯源 |
| **design** | `agents/design.md` | 设计 / 交互：页面结构 + 黑白线框 |
| **tech** | `agents/tech.md` | 技术可行性：能不能做、多贵、什么坑 |
| **growth** | `agents/growth.md` | 增长运营：漏斗 / 转化 / 指标 / A-B + **SEO 巡检 × 技术协作**（发现问题→数据证明→提需求→验收→复盘） |
| **review** | `agents/review.md` | 挑刺：定稿前找漏洞和风险 |

**统一底层原则**（所有 Agent 共用）：
> 发现问题 → 提出假设 → 验证 → 产出 → 获得反馈 → 迭代
> 必须区分标注：✅ 已验证事实 · 📊 数据事实 · 💬 用户反馈 · ❓ 未验证假设 · 🤖 推测

## 三、常用命令（终端）

```bash
aios list        # 列出 9 个 Agent
aios pm          # 看产品经理角色卡（content / ops / review … 同理）
aios flow        # 看整体流程
aios docs        # 列出 docs/ 里的文档
aios open        # 在访达里打开这个文件夹
```

---

## 四、怎么改（三种场景）

**1. 你自己改**
直接编辑 `agents/` 里的 md 文件（普通文本，用「文本编辑」就能开）。

**2. 让 AI 改（推荐）**
说：「读 `AI-Agent/README.md`，把 ops 角色卡里的『活动 9 步』改一下，加上 XX」——
AI 读完就知道去哪改、改成什么样。

**3. 加一个新 Agent**
1. 在 `agents/` 新建 `xxx.md`（照现有卡片的格式写：一句话 / 什么时候用 / 输出 / 边界）
2. 在 `aios` 脚本的 `ORDER` 和 `TITLE` 里加一行
3. 在本 README 的表格里加一行
4. 告诉 AI 一声，它会同步到自己的技能里

## 五、改完之后怎么验证

```bash
aios list        # 能看到就行
aios <改的那个>   # 内容对不对
```

改动较大时（比如改了铁律），**告诉我一声** —— 我会把规则同步到我的技能里（我平时自动遵守的那份），不然只改卡片我可能跟不上。
