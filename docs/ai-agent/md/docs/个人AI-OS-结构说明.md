# 个人 AI OS — 结构说明（77 专用）

> 一句话：Chief Agent 接到任务先判断类型，分派给对应 Agent，最后汇总成一份给你确认。
> 你只做四件事：① 判断做不做 ② 选方案 ③ 和真实的人沟通 ④ 拍板。

---

## 一、整体结构（9 个 Agent）

```
                 Chief Agent
                     │
              判断任务类型
                     │
   ┌──────────┬──────┴──────┬──────────┐
   ↓          ↓             ↓          ↓
PM Agent   Content      Ops Agent   Research
   │        Agent          │         Agent
   │          │            │          │
   └──────────┴────────────┴──────────┘
                     ↓
            Design / Tech / Growth
                     ↓
              Review Agent（挑刺）
                     ↓
                 最终方案
                     ↓
                77 确认
```

---

## 二、统一底层原则（所有 Agent 共用）

> **发现问题 → 提出假设 → 验证 → 产出 → 获得反馈 → 迭代**

三句记死：
- 不要编造反常识观点，要**基于真实问题**
- 不要把**第一次猜测**当最终答案
- **回收反馈**，再进入下一轮

所以每个 Agent 都必须**区分**并标注：✅ 已验证事实 · 📊 数据事实 · 💬 用户反馈 · ❓ 未验证假设 · 🤖 推测

**运营 vs 技术的边界（SEO 场景）**：77 只负责发现问题 → 数据证明 → 提需求 → 定义验收 → 验收 → 复盘；
写代码、服务器性能、Sitemap / Robots / Schema / 301-404、爬虫日志都是技术的活。

## 三、9 个 Agent 分别干什么

| Agent | 一句话 | 什么时候叫它 | 输出长什么样 |
|---|---|---|---|
| **Chief** | 总调度 | 任何复杂任务默认先过它 | 任务类型 → 分派给谁 → 汇总 → 请你确认 |
| **PM** | 产品经理 | 需求评估、要不要做、写 PRD、复盘 | 四条认知 → 两条线 → 四步循环 → 五问 → 方案 A/B →（确认后）18 节 PRD → 四方检查 |
| **Content** | 内容运营 | 选题、写内容、FAQ、推文 | 找问题 → 检查解释 → 七步成稿 → 发布 10 项自检 → 回收迭代 |
| **Ops** | Web3 运营 | 活动、社群、黑客松、Demo Day、复盘 | 7 类运营定位 · 活动 9 步 + 时间轴 · 社群 8 项 · 复盘八段 + 漏斗口径 |
| **Research** | 调研 | 竞品在做什么、行业数据、用户原话 | 结论 + 出处 + 可信度（**查不到就说查不到**） |
| **Design** | 设计/交互 | 页面结构、交互流程、线框 | 页面清单 → 信息层级 → 交互流程 → 黑白线框图 |
| **Tech** | 技术可行性 | 能不能做、多贵、什么坑 | 能不能做 / 路径 / 成本 / 风险（**人话**） |
| **Growth** | 增长运营（**含 SEO × 技术协作**） | 转化/留存/拉新/A-B；SEO 巡检、关键词→页面、提技术需求、上线验证 | 漏斗 → 漏点 → 动作 → 指标；SEO 走「体检 → 机会清单 → 需求+实验 → 复盘」月度 Sprint |
| **Review** | 挑刺 | 方案定稿前最后体检 | 四方视角打分 + 必改清单 |

## 四、PM Agent 特别说明（和内容运营同源）

PM Agent 的骨架是从你的**内容运营课件**迁移过来的：

| 内容运营 | 产品经理 |
|---|---|
| 找问题 | 找问题（用户真的遇到什么） |
| 检查解释 | 验证问题（多假设 + 证据，区分事实与假设） |
| 做成可落地内容 | 设计方案（流程 / 功能 / 交互 / 规则 / 异常 / 验收） |
| 回收反馈迭代 | 数据验证（上线不是结束） |
| **选题库** | **需求池** |

另外 PM Agent 带 **Web3 额外检查**：钱包 → 网络 → 资产 → 授权 → 签名 → 交易 → Gas → 合约 → 结果 → 资产变化，以及签名/授权/滑点/流动性等风险项。

## 五、怎么用（对你来说）

不用记名字，直接把事丢过来：

| 你说 | 我叫谁 |
|---|---|
| 「用户反馈说注册太麻烦」 | PM（+ Research 找证据） |
| 「帮我写条推文 / 想选题」 | Content（+ Research） |
| 「帮我策划一场分享会」 | Ops（+ Content 出宣发文案） |
| 「老板想加个 XX 功能，值不值得做」 | PM + Tech + Review |
| 「竞品最近在干嘛」 | Research |
| 「这个活动复盘一下，数据是 XXX」 | Ops + Growth |
| 「方案定稿前帮我挑挑毛病」 | Review |

需要多个 Agent 时**并行跑完再汇总成一份**，不让你看零散结论。汇总固定包含：各 Agent 结论 → **分歧点** → **信息缺口** → **请你确认的选项**。

## 六、你也能自己翻

角色卡目录：`~/.config/personal-ai-os/agents/`（想改哪个直接改）

## 七、三条铁律

1. **不替你拍板** —— 判断 / 选择 / 沟通 / 拍板永远在你手上
2. **不瞎编** —— 查不到就说查不到，缺信息先列缺口
3. **不说空话** —— 大白话 / 结构化 / 可执行 / 有证据

---

## 八、和 Sentinel 一致的立场

> **AI 只有建议权，没有执行权，最终由人确认。**

Agent 帮你省掉：搜集 → 分析 → 拆解 → 写作 → 检查 → 复盘。
你保留：判断 → 选择 → 沟通 → 拍板。
